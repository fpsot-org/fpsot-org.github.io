Public services should run on open technology.

The Foundation for Public Sector Open Technology (FPSOT) helps governments and public institutions adopt, build, and sustain software that is transparent, interoperable, and community-owned.

We work at both ends of the problem: the policy and procurement frameworks that make open technology adoptable, and the code and reference implementations that make it deployable.

Get involved on GitHub

What we do

Support the public sector

Guidance, reference architectures, and best practices for governments adopting open source and open standards.

Build and maintain open technology

Reusable, government-grade open source components and reference implementations.

Advocate for policy change

Procurement, funding, and legal frameworks that prioritize open technologies and digital sovereignty.

Educate and connect

Learning resources, worked examples, and communities of practice for public servants, vendors, and contributors.

What we're working on first

  • Reference architectures for modern public-sector systems
  • Policy & procurement templates for FOSS-friendly RFPs
  • Sample projects showing how to build government-ready systems with open technologies
  • Migration playbooks for moving from proprietary stacks to open source

All of this is in progress and shaped in the open — early input is welcome.

Specifications

  • Writing: how FPSOT writes text for people, in plain English and French
  • Documentation: how each specification is documented, published and compared by jurisdiction
  • Version control: signed commits, branches, merges and releases
  • Naming: names that machines read, from repositories to API paths, fields and events
  • Internationalization: language tags, formatting, messages, translation files, names and addresses
  • Data types: dates and times, time zones, money, identifiers and multilingual text
  • RESTful APIs: HTTP, OpenAPI descriptions, errors, pages, versions, security and events
  • Accessibility: WCAG 2.2 AA for web pages, documents and apps, testing, conformance statements and procurement
  • Diagrams: diagrams as code with C4, UML, BPMN and generated data models, in two languages
  • Style: design tokens, component behavior and themes for PatternFly, Canada and Québec
  • Vocabularies: code lists and classifications as SKOS concept schemes, in English and French
  • Data models: entity models written in LinkML, starting with Party, with generated JSON Schema, SQL, OWL and SHACL
  • Testing: test levels, BDD with Gherkin in two languages, contract tests, conformance suites and synthetic test data
  • Security: secure development, supply chain, secrets, and a coordinated disclosure policy with private notice for public bodies
  • Observability: logs, traces and metrics with OpenTelemetry, audit and business events, retention, tamper evidence and process mining
  • Identity and access: sign-in with OpenID Connect, assurance levels, sessions, tokens, representation, and authorization through AuthZEN
